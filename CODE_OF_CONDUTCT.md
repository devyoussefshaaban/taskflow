# Code of Conduct

## Our Commitment

TaskFlow is an open-source project created and maintained by [Youssef Shaaban](https://www.linkedin.com/in/imdevyoussefshaaban/).

We are committed to providing a welcoming, respectful, and constructive environment for everyone who participates in the project.

We welcome contributions from people with different backgrounds, experience levels, perspectives, and technical expertise.

All contributors, maintainers, reviewers, and community members are expected to participate professionally and respectfully.

---

## Expected Behavior

Participants are expected to:

- Be respectful and professional in discussions and reviews.
- Assume good intentions and communicate constructively.
- Provide thoughtful and actionable feedback.
- Focus on the technical problem rather than the person.
- Be open to different approaches and perspectives.
- Respect differing levels of experience and expertise.
- Accept constructive criticism gracefully.
- Help maintain a welcoming environment for new contributors.
- Keep discussions relevant to the project.
- Respect project decisions made by maintainers.

---

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, discrimination, intimidation, or personal attacks.
- Trolling, insulting, or deliberately hostile comments.
- Personal or political attacks unrelated to the project's technical goals.
- Publishing private or personally identifying information without permission.
- Threats of violence or intimidation.
- Sexualized language or unwanted sexual attention.
- Deliberate disruption of discussions, issues, or pull requests.
- Repeatedly ignoring project guidelines or maintainer requests.
- Any other behavior that would reasonably be considered inappropriate or harmful in a professional open-source community.

---

## Technical Discussions

Technical disagreement is normal and encouraged when it helps improve the project.

Contributors may challenge:

- Architectural decisions
- Implementation approaches
- API design
- Database design
- Performance decisions
- Tooling choices
- Documentation

However, disagreements should remain focused on the technical issue.

Prefer:

> "I think this approach could cause problems with database consistency because..."

Instead of:

> "This is a terrible implementation."

Strong technical opinions are welcome. Personal attacks are not.

---

## Pull Request and Code Review Conduct

Code review should focus on improving the code and the project.

Reviewers should:

- Explain why a change is being requested.
- Provide actionable feedback.
- Distinguish required changes from optional suggestions.
- Avoid personal or dismissive language.

Contributors should:

- Respond professionally to review feedback.
- Explain their reasoning when they disagree.
- Avoid taking technical criticism personally.
- Be willing to revise their implementation when appropriate.

Maintainers have the final responsibility for deciding whether a contribution fits the project's architecture, quality standards, and direction.

---

## Scope

This Code of Conduct applies to all project spaces, including:

- GitHub issues
- Pull requests
- Code reviews
- Discussions
- Documentation
- Project-related communication
- Other spaces where participants are representing or directly interacting with the TaskFlow community

## Enforcement

The project maintainer is responsible for enforcing this Code of Conduct.

Depending on the circumstances, violations may result in:

1. A private or public warning.
2. Removal of inappropriate comments or content.
3. Temporary restriction from participating in project discussions.
4. Temporary or permanent restriction from contributing.
5. Removal of access to project resources.
6. Other appropriate actions necessary to protect the project community.

The response will depend on the severity and circumstances of the violation.

Serious or repeated violations may result in immediate removal from project spaces.

---

## Maintainer Responsibility

The maintainer may remove, edit, or reject comments, issues, pull requests, or other contributions that violate this Code of Conduct or negatively affect the project community.

Maintainer decisions should be made with the long-term health, safety, and quality of the project in mind.

---

## Good-Faith Participation

This Code of Conduct is intended to establish reasonable expectations for participation, not to discourage legitimate technical disagreement.

Contributors are encouraged to:

- Ask questions.
- Challenge assumptions.
- Suggest alternatives.
- Report problems.
- Discuss architectural trade-offs.
- Disagree respectfully.

Healthy disagreement is an important part of open-source development.
